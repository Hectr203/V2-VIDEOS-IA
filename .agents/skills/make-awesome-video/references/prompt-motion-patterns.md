# prompt-motion 갤러리에서 뽑은 패턴

[prompt-motion.com](https://prompt-motion.com)은 Claude가 만든 모션 영상과 **그 영상을 만든 프롬프트 원문**을 짝지어 모아 둔 갤러리다. 이 문서는 2026-10-08 기준 232개 항목(프롬프트 229, 스킬 3)을 전부 읽고, 결과가 좋은 영상의 프롬프트가 공통으로 지시하는 것을 이 스킬의 단계별로 정리했다. 기법은 이 스킬의 말로 다시 썼고 원문은 옮기지 않았다. 영상과 프롬프트는 각 크리에이터의 것이다. 원문은 링크나 `find_motion_refs.py --show <slug>`로 읽고, 결과물이나 이 문서에 문장을 옮기지 않는다.

```bash
python3 {baseDir}/scripts/find_motion_refs.py "launch" --structured --details   # 상세 스펙형 프롬프트
python3 {baseDir}/scripts/find_motion_refs.py kinetic type --aspect square
python3 {baseDir}/scripts/find_motion_refs.py --show ultimaxbt-bbebf5          # 원문 읽기
bash {baseDir}/scripts/analyze_ref.sh "<video URL>" refs/<slug> --fps 4          # 갤러리 mp4를 바로 분석
```

## 갤러리가 보여주는 것

- **절반 가까이가 짧은 프롬프트다.** 73개는 사실상 같은 문장("15초짜리 모션 그래픽, 이력서용 쇼릴처럼, 전력으로")을 복사했고, 많은 경우 제품 이름만 붙였다. 결과는 대개 키네틱 타이포 + 도형 + 파티클 쇼릴로 수렴하고 서로 닮았다. 이 스킬 입장에서 이것이 **가장 흔한 실제 요청 형태**다: 참조 없음, 소재 거의 없음, "알아서 멋지게". 대응은 아래 "참조 없는 쇼릴 요청" 섹션.
- **눈에 띄게 다른 영상은 상세 스펙형 프롬프트에서 나온다** (`--structured`, 17개). 이것들은 거의 같은 뼈대를 쓴다: 입력 → 방향(금지 목록 포함) → 비트 단위 구조 → 빌드 규칙 → 함정 → 시작 절차. 이 뼈대는 [film-spec-template.md](film-spec-template.md)로 옮겼다.
- 스택이 적힌 55개 중 Remotion 12, HyperFrames 10, 순수 HTML/JS/Canvas + Playwright 캡처 다수, Three.js 5. 상세 스펙형 다수는 "한 HTML 파일 + `seek(t)` 순수 함수 + Playwright 프레임 캡처 + ffmpeg" 구조다. 이 스킬의 결정적 모션 규칙과 같은 계약이다.
- 반복 표기가 있는 96개 중 89개가 "One-shot"이다. 원샷이 이 정도로 나오는 이유는 프롬프트가 이미 감독 역할(금지 목록, 비트 구조, 정지 프레임 확인 절차)을 하고 있어서다. 이 스킬의 게이트가 하는 일과 같다.

## 1. 참조 없는 쇼릴 요청 ("보여줘", "전력으로")

`motion` 모드는 원래 참조 영상을 받는다. 참조가 없으면 갤러리에서 고른다.

1. 요청의 소재로 검색한다: 제품이 있으면 `launch` 계열, 없으면 `showreel`, `kinetic`, 스타일 단어(`pixel`, `paper`, `risograph`, `whiteboard`).
2. **서로 다른 방향**의 후보 3–4개를 포스터와 함께 G1에 제시한다. 공유 쇼릴 프롬프트 결과끼리는 서로 닮았으니 한 개까지만 넣는다. 구조화 프롬프트 결과(한 요소가 계속 변신하는 영상, 연속 카메라 영상, 단어가 구조물이 되는 영상 등)를 섞는다.
3. 고른 영상은 `analyze_ref.sh`로 분석하고, 그 프롬프트 원문은 **방향과 금지 목록을 읽는 용도**로만 본다.

참조 없이 바로 만들어야 하면(사용자가 게이트 생략을 명시) 아래 원칙 2–4를 기본값으로 쓴다.

## 2. 방향: 하나의 연속된 생각

좋은 프롬프트는 효과 목록 대신 **한 줄의 원칙**으로 방향을 준다. 이 스킬의 시그니처 변형과 넘겨지는 물체([motion-grammar.md](motion-grammar.md))를 더 강하게 밀어붙인 형태다.

- **한 요소가 모든 장면을 관통한다.** 주황 점 하나가 UI 토글 → 글자 위 점 → 스프링 그래프를 그리는 점 → 화면을 채우는 원 → 엔드 카드로 이어진다 ([ultimaxbt-bbebf5](https://prompt-motion.com/ultimaxbt-bbebf5)). 도형 하나가 버튼 → 로더 → 플레이어 → 슬라이더 → 탭 → 차트로 컷 없이 변한다 ([twoclipping-5cba86](https://prompt-motion.com/twoclipping-5cba86)).
- **다음 장면은 이전 장면으로 만든다.** 페이드·블러·컷 대신 모양이 바뀐다. 검은 도형이 화면을 덮었다가(flood) 다음 장면의 물체로 줄어든다(contract). 차트 선이 문서의 모서리가 되고, 숫자가 인보이스 금액이 된다 ([daniel-haida-8691d4](https://prompt-motion.com/daniel-haida-8691d4)). 판정 기준: 보는 사람이 "당연히 저기서 나왔지"라고 느끼는가.
- **단어에 역할을 준다.** 말을 화면에 올리는 데서 그치지 않고, 단어가 구조물이 된다(WAIT는 상인방, VOICE는 기둥, FLOOR는 바닥판). 마지막 문장은 앞선 단어들이 실제로 쌓은 것 위에 선다 ([gdgtify-287ddf](https://prompt-motion.com/gdgtify-287ddf)).
- **이야기 축 하나.** 기능 다섯 개 나열 대신 혼돈 → 통제 → 명료 → 브랜드, 또는 문제 → 하는 일 → 3단계 작동 → 증거 하나 → 이름, 또는 시장이 왜 중요한가 → 왜 지금 아픈가 → 어떻게 고치나 → 무엇을 얻나.
- **"평범한 것 세 개보다 대단한 순간 세 개."** 15초에 시각 아이디어 약 4개. 모든 중요한 프레임은 그 자체로 정지 광고가 될 수 있어야 한다.
- **실제 카메라 촬영처럼 생각한다.** 소프트웨어라도 고급 실물 제품을 매크로로 찍는다고 상상한다. 조명은 아주 약한 림 라이트, 지나가는 스펙큘러, 절제된 비네트 정도. 제품을 시네마틱하게 보이려고 흐리게 만들지 않는다.

## 3. 금지 목록 (G2 스토리보드에 명시)

스펙형 프롬프트는 거의 모두 **금지 목록**을 가진다. 금지 목록이 있으면 에이전트가 기본값 효과로 돌아가지 못한다. 스토리보드 각 안에 그 안의 금지 목록을 적는다. 아래는 여러 프롬프트에서 반복된 항목이다 (방향에 맞는 것을 고른다. 예를 들어 하이프 에디트에는 카메라 셰이크가 맞을 수도 있다).

| 범주 | 반복된 금지 항목 |
|---|---|
| 효과 남용 | 충격파 링, 파티클 버스트, RGB 분리, 카메라 셰이크, 렌즈 플레어, 네온 글로우, 그리드 바닥, 깜빡이는 배경, 글리치, 줌 블러 남발 |
| 전환 | 크로스페이드, 블러 인, 랜덤 와이프, 회전 전환, 2초마다 휩 팬, SaaS식 왼쪽 슬라이드, 의미 없이 도는 3D 카드 |
| 이징 | 튀는(bouncy) 이징, 만화 같은 스프링 (오버슈트는 2% 이하 또는 "아주 작게"), 선형 이동 |
| 표면 | 모든 곳의 글래스 카드, UI 크롬 위 그라데이션, 보라색 AI 그라데이션, 무지개 그라데이션, 과한 블러 |
| 텍스트 | 화면 위 마침표, 애니메이터 용어("squash", "stagger", "easing")를 화면에 쓰기, 아이브로 라벨, 마케팅 문단, 단어마다 따로 튀는 타이포 |
| AI 티 | 화면 모서리의 프레임·텍스트 장식, 타임코드·fps·스크러버 같은 가짜 크롬, 베이지 "아트풍", 템플릿처럼 보이는 모든 것 |

## 4. 페이싱 수치

- 첫 1–1.5초 안에 이미 프리미엄으로 보여야 하고, 첫 제품 순간은 약 2초 안에. 첫 프레임에 훅.
- 1.5–2초마다 새 아이디어. 비트마다 무언가 일어난다.
- 아이디어당 한 샷, 한 가지 주 움직임. "전환마다 주 움직임 하나."
- 정지는 **의도한 곳 한 번만** (예: 수평이 처음 맞는 순간 400ms 완전 정지, 엔드 카드 홀드). 그 외는 계속 살아 있다.
- 마지막 프레임은 등록될 만큼 충분히 머문다. 루프면 마지막 프레임 = 첫 프레임 (커서 위치와 속도까지).

## 5. 비트 그리드로 구조를 쓴다

스펙형 프롬프트는 초가 아니라 **마디·박**으로 구조를 쓴다. 이 스킬에서는 음악이 있으면 스토리보드 장면 표의 시간 열을 박 단위로도 적는다 (`storyboards/music-map.md`와 같은 그리드).

- "120 BPM, 10마디, 마디당 2초", "46박: b0–2 …, b13–16 드롭에서 하드 컷 세 번 …"처럼 쓴다. 모든 컷은 다운비트, 모든 UI 히트는 박 위.
- 드롭 위치를 정하고 거기에 가장 큰 순간을 둔다 (줌 착지, 다크 스위치, 보이스오버의 동사 줄).
- 하드 컷을 박보다 **2프레임 앞에** 두는 프롬프트가 있다 (이유는 적혀 있지 않다). 컷이 박에 늦어 보이면 시도해 볼 값이다.
- 음악을 목표 BPM에 맞춰 늘리고(conform), 비트 그리드를 실제 킥 타격에 보정한다. 자동 BPM을 믿지 않는다 ([audio.md](audio.md)).
- **말이 중심이면 박에 억지로 맞추지 않는다.** 구절·쉼·강조로 큐 시트를 만든다 ([gdgtify-287ddf](https://prompt-motion.com/gdgtify-287ddf)).
- 모든 큐는 한 파일(`timeline.ts`, 박 단위)에, 모든 문구는 다른 한 파일(`copy.ts`)에. 장면 코드에는 매직 넘버를 두지 않는다 ([antonio-kodheli-490109](https://prompt-motion.com/antonio-kodheli-490109)). HyperFrames에서도 같은 원칙으로 장면 시작 시각을 상수 표 하나에 둔다.

## 6. 카메라와 커서

- **세계 레이어 하나 + 카메라 트랙.** 장면 전체를 월드 좌표에 한 번 배치하고, 카메라를 (초점 x, 초점 y, 로그 스케일) 트랙으로 움직인다. 타일이 풀 블리드에 가까워질수록 모서리 반경을 0으로 보내면 풀백·휩 인·매치 컷이 정확히 이어진다.
- **카메라 동작은 한 번에 하나.**
- **계속 흐르는 드리프트:** 장면마다 1.0→1.04 정도로 천천히 밀고, 다음 장면은 이전 장면이 끝난 줌에서 시작한다. 핸드오프에서 1.0으로 리셋하면 줌이 튄다.
- **샷은 이미 움직이며 들어오고, 가속하거나 블러 램프로 나간다.** 정지한 프레임에서 컷하지 않는다. 지수 감속 진입(매 프레임 남은 거리의 12–19%)이 한 예다. 블러는 속도와 방향을 따른다.
- **스크린 스튜디오식 줌:** 각 순간이 화면을 채우도록 카메라가 다가가고, 커서도 같이 커진다.
- **커서는 연기한다.** macOS 화살표 하나를 재사용하고, 가는 방향으로 고개를 돌리고, 호버에서 커지고(약 1.5배), 누를 때 15% 줄어든다. 카메라가 홀드 중에도 기어가므로 커서는 버튼의 **실시간 위치**를 따라간다. "커서가 모든 변화를 일으킨다"는 방향은 원인 → 결과 규칙([motion-grammar.md](motion-grammar.md))의 가장 강한 형태다.

## 7. 모션 수학

- **닫힌 형태 스프링.** 스프링을 계단 응답 공식으로 계산해 시간의 순수 함수로 유지한다. 목표가 여러 번 바뀌는 값은 **변경마다 스프링 하나씩을 더한 합**으로 쓴다 (적분 상태 없음, 어느 프레임으로 seek해도 같다).
- **양 끝을 다른 스프링으로.** 탭 인디케이터·토글 손잡이의 앞 가장자리와 뒷 가장자리를 다른 스프링에 태우면 앞이 먼저 늘어나는 액체 같은 늘어남이 나온다.
- 그래프와 그 위의 점은 **같은 함수**로 움직인다. 다르면 스프링이 가짜처럼 보인다.
- 직접 조작: 커서가 누르고 있는 동안 값은 커서 위치로 계산하고, 놓으면 그 자리에서 스프링으로 돌아간다.
- 프리미엄 감속 곡선의 예: `cubic-bezier(0.16, 1, 0.3, 1)`. 요소마다 도착 시각을 미세하게 다르게, 장면 사이에 속도를 이어받는다.
- 값은 프레임 번호에 대해 연속이어야 한다 (반 프레임을 렌더하는 60fps 마스터 대비). 모션 계산에 `Math.floor`를 쓰지 않는다. 키프레임 표 `kf(frame, [[f, value], ...], ease)` + 선형 보간이 쓰기 편하다.
- 프레임 단위로 정확한 스펙이 필요하면 좌표·크기·블러를 프레임별 표로 적는 방식도 있다 ([notdwd-7de38a](https://prompt-motion.com/notdwd-7de38a): 12초에 360프레임 표). 참조를 정밀 재현하는 `motion` 모드 샷 리스트의 극단적인 형태다.

## 8. 화면 소재

- **스크린샷을 그대로 띄우지 않는다.** 컴포넌트·아이콘으로 분해하거나 실제 디자인 시스템으로 다시 만들어 영역별로 움직인다 ([ho-ba-f3f0e9](https://prompt-motion.com/ho-ba-f3f0e9), [daniel-haida-8691d4](https://prompt-motion.com/daniel-haida-8691d4)).
- 실제 사이트의 페이지(홈, 모바일 뷰, 다크 모드)를 브라우저로 캡처해 브라우저·폰 프레임 안에서 움직인다. 화면의 사실과 숫자만 쓴다 ([wani-shola-16ca7a](https://prompt-motion.com/wani-shola-16ca7a)).
- 로고는 실제 파일을 SVG로 트레이스해 날카롭게, 애니메이션 가능하게. 다시 그리거나 근사하지 않는다. 박스 안에 든 로고 파일을 그대로 쓰지 않는다.
- 사이트·갤러리 자체를 소재로 쓰면 크리에이터 핸들처럼 원본에 붙은 표기를 그대로 유지한다.
- 실사 푸티지는 JPEG 시퀀스로 뽑아 프레임마다 소스를 바꾸거나, 전부 인트라 프레임으로 재인코딩(`ffmpeg -g 1`)해 seek가 정확하게 한다.

## 9. 사운드

[audio.md](audio.md)에 이어 갤러리에서 반복된 것:

- **효과음은 파일 시작이 아니라 측정한 피크를 이벤트에 맞춘다.** 라이저는 4초짜리가 많으니 피크 주변으로 잘라 쓴다.
- 나타나는 요소마다 부드러운 효과음 하나, 나머지는 침묵. 효과음은 음악 밑에 조용히.
- 트랙 자체의 브레이크는 역재생 휘시로 다음 히트까지 채운다.
- 보이스오버가 있으면: 대본 테이크 4개를 한 번에 생성해 고르고, 어색한 줄만 4번 다시 생성해 끼운다. 0.28초 넘는 쉼은 0.2초로 줄인다. 단어 타이밍은 100ms 이상 쉼에서 잘라 구간별로 전사하고 첫 단어를 실제 온셋에 맞춘다 (한 번에 전사하면 0.5초까지 늦게 잡힌다). 음악은 3밴드 사이드체인으로 덕킹하고, 300Hz–4kHz에서 목소리가 음악보다 약 9dB 위에 오게 구절별로 맞춘다 ([rossaxbt-3085b7](https://prompt-motion.com/rossaxbt-3085b7)).
- 마스터 −14 LUFS, −1 ~ −2 dBTP, **AAC 인코딩 후 다시 측정**.
- 라이선스가 확인된 음원이 없으면 저작권 음악을 가져오지 않는다. 화면 마스터 + 음악·효과음이 맞을 지점을 적은 큐 시트로 낸다.

## 10. QA 절차

스펙형 프롬프트는 렌더 전에 멈추는 지점과 검사를 직접 지시한다. 이 스킬의 G3·크리틱과 같은 생각이고, 추가로 쓸 것:

- **박마다 1프레임**(또는 컷마다 정지 프레임)을 먼저 렌더해 그리드에서 벗어난 것, 비좁은 것, 읽기 어려운 것을 고친다. 전체 렌더 전에 20프레임 이상 찍어 본다.
- **단일 프레임 팝 검사:** 이웃 프레임 대비 차분이 3배 넘게 튀는 프레임을 찾는다. 의도한 하드 컷과 16분음표 이미지 연타만 예외.
  ```bash
  python3 {baseDir}/scripts/frame_pops.py renders/draft.mp4 --allow 2.47,3.37 --allow-range 8.0-9.0
  ```
- 브라우저 스크린샷이 아니라 **최종 MP4에서 디코딩한 프레임**으로 검수한다.
- 자기 결과를 거절할 기준을 명시한다: SaaS 템플릿, 파워포인트 애니메이션, 웹사이트 화면 녹화, 슬라이드되는 스크린샷 다섯 장, 과한 마케팅 문구처럼 보이면 다시 한다. "프로 디자이너가 한 것 같지 않으면 처음부터 다시"라는 지시가 원샷 품질을 끌어올린 사례가 있다.

## 11. 구현 함정 (HTML/CSS/Canvas)

HyperFrames 장면에도 그대로 적용되는 것:

- `preserve-3d` 요소에 `opacity`나 `filter`를 걸면 평면화되어 양면이 다 보인다. 감싼 요소를 페이드한다.
- 카메라가 스케일하는 요소에 `will-change`를 걸면 글자가 흐리게 렌더된다.
- 모양이 변하는 컨테이너 안에서 바뀌는 글자는 **자기 마스크와 등장·퇴장 타이밍**을 따로 가져야 겹치지 않는다.
- 화면을 덮는 flood는 네 모서리를 넘게 스케일하고 약 0.3초에 걸쳐야 한다. 아니면 화면 절반이 한 프레임에 바뀐다 (팝 검사에 걸린다).
- 숨긴 부모 안의 `visibility: visible` 자식은 비쳐 보인다. `inherit`를 쓴다.
- 흰 페이지 위 흰 요소(카드, 궤도 사각형, 타일)는 1px 헤어라인과 옅은 그림자가 없으면 사라진다. 페이지 색과 클립 배경이 같아도 타일이 사라진다.
- 0.05초 페이드는 그냥 팝처럼 보인다. 사라지지 않게 할 거면 0.3초 이상.
- 글자 뒤 하이라이트 박스는 텍스트 선택 영역처럼 보인다. 형광펜 스윕을 쓴다.
- 블러 표가 과하면 도형이 통째로 지워진다. 프레임이 비어 보이면 형태가 읽힐 때까지 블러를 낮춘다.
- 카메라 푸시의 마지막 프레임을 확인한다. 헤더·메타 줄이 가장자리 띠로 밀려나곤 한다.
- 이름 길이가 바뀌면 락업 전체(간격·이름·필)를 함께 스케일한다. 필 하나만 화면 밖으로 밀려나지 않게.
- 컷이 많은 클립을 루프로 쓰면 장면 감지로 컷 없는 구간만 골라 루프하고, 이웃 타일이 같은 프레임에 바뀌지 않게 위상을 엇갈린다.
- 로컬 `python -m http.server`는 비디오 범위 요청을 못 해 seek가 안 된다. blob URL로 읽는다.
- 리퀴드 글래스: Chromium에서 `backdrop-filter: url()`은 변위 맵을 잘못 읽는다. 뒤 장면의 복제본에 SVG `feDisplacementMap`을 스케일을 조금씩 달리해 세 번 걸면 색수차 가장자리가 나온다. 캔버스라면 뒤를 약 14px 블러 + 가장자리 12px 띠를 약 1.06배 확대 + 밀키·광택·림·그림자. 흰 바탕에서는 유리가 안 보이니 옅은 오라나 사진의 블러 워시를 뒤에 깐다.
- 구(goo) 효과: 블러 + 알파 임계값 후 원본을 그 위에 합성하면 안쪽은 선명하게 남는다.
- 가변 폰트 단어를 한 점으로 압축할 때 글자마다 같은 비율로 점을 향해 움직이고 `wdth` 축을 함께 좁히면 글자가 계속 맞닿는다.

모션 블러는 여러 상세 프롬프트가 프레임당 3–8개 서브프레임을 렌더해 ffmpeg `tmix`로 섞는 방식을 쓴다. HyperFrames 렌더러에 같은 옵션이 있는지는 확인되지 않았으니 이 스킬에서는 참고 기법으로만 두고, 필요하면 블러를 속도에 비례하는 방향성 블러로 장면 안에서 그린다.
