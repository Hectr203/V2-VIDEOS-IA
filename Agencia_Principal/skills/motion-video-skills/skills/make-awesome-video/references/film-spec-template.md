# 필름 스펙 (`film-spec.md`)

G2에서 방향(또는 `motion` 샷 리스트)이 승인되면, 빌드 전에 brief + 스타일 스펙 + 승인된 스토리보드를 **한 장의 필름 스펙**으로 합친다. 빌드하는 에이전트(나 자신, 서브에이전트, 다음 세션)는 이 파일 하나만 읽고 만든다. 각 장면 코드를 쓸 때도 이 파일을 기준으로 삼는다.

형식은 prompt-motion 갤러리에서 결과가 좋았던 상세 스펙형 프롬프트들이 공통으로 쓰는 6블록 뼈대를 이 스킬에 맞춘 것이다 ([prompt-motion-patterns.md](prompt-motion-patterns.md)). 예시로 원문을 읽으려면 `python3 {baseDir}/scripts/find_motion_refs.py --structured`.

## 6블록과 게이트

| 블록 | 담는 것 | 이 스킬에서 채우는 시점 |
|---|---|---|
| `inputs` | 사용자에게 받은 것 + 빠진 항목의 기본값 | 0단계 인테이크 (`brief.md`에서 옮김) |
| `direction` | 한 줄 원칙, 연속 모티프, 스타일(색·서체·질감), **금지 목록** | G1 스타일 스펙 + G2 선택안 |
| `structure` | 박/마디(또는 초) 단위 장면 흐름, 컷·드롭·히트 시각 | G2 장면 표, 음악이 있으면 `music-map.md` 그리드로 |
| `build` | 결정적 렌더 계약, 시간·문구 상수 위치, 오디오 배치, 검사 | 2단계 엔진 선택 + 5단계 계획 |
| `gotchas` | 이 영상에서 깨지기 쉬운 지점 | [gotchas.md](gotchas.md)·패턴 문서에서 해당하는 것만 + G3에서 발견한 것 |
| `start` | 멈춤 지점 | G3 정지 프레임 목록(어느 시각 몇 장) + G4 전 크리틱 |

스펙형 프롬프트의 시작 절차("입력을 묻고 → 비트 그리드 위 스토리보드 → 정지 프레임 4장 → 전체 렌더")는 이 스킬의 G1–G3와 같은 순서다. 필름 스펙은 그 사이를 이어 주는 문서이고, 게이트를 대신하지 않는다.

## 템플릿

```markdown
# Film spec — <제목>

<inputs>
받은 것: 제품명, 한 줄 약속, 로고(assets/logo.svg), 스크린샷 5장(assets/screens/), 브랜드 #0C0F1A / #E8B84B, 서체 Plus Jakarta Sans, 음원 assets/music.mp3 (라이선스: …)
기본값으로 정한 것: 길이 15s, 1920x1080, 60fps, 보이스 없음
</inputs>

<direction>
한 줄: <예: 금색 점 하나가 대시보드 → 영수증 → 인보이스 → 워드마크를 잇는 하나의 생각. 혼돈 → 통제 → 명료 → 브랜드.>
연속 모티프: <장면을 관통하는 요소와 각 장면에서의 역할>
스타일: 캔버스 / 잉크 / 액센트 HEX, 서체와 굵기, 질감(종이, 유리, 금속 …), 카메라 언어(연속 테이크 / 하드 컷 리듬)
이징: <예: 감속 cubic-bezier(0.16,1,0.3,1), 오버슈트 2% 이하>
금지: <이 영상에서 쓰지 않을 것 6–10개. prompt-motion-patterns.md "금지 목록"에서 고르고 이 영상만의 것을 더한다>
사실: 화면의 모든 주장은 brief.md 출처. 지어낸 수치·고객사 없음.
</direction>

<structure>
120 BPM, 30박 (0.5s/박). 드롭 b8.
b0–2   첫 프레임 = 완성된 구도. <무엇>
b2–8   <장면> → 넘겨지는 물체: <A의 무엇이 B의 무엇이 되는가>
b8     드롭: <가장 큰 순간>
...
b26–30 락업: <워드마크 + 한 줄>, 마지막 프레임 1.5s 이상 (루프면 첫 프레임과 동일)
</structure>

<build>
1. 엔진: HyperFrames (또는 Remotion). 모든 상태는 타임라인 시간의 순수 함수. 무작위는 시드 해시.
2. 장면 시작 시각·히트 시각은 상수 표 하나(박 단위), 모든 화면 문구는 다른 한 곳. 장면 코드에 매직 넘버 없음.
3. 스프링이 필요하면 닫힌 형태, 목표 변경마다 스프링 합산.
4. 효과음은 측정한 피크를 이벤트 시각에. 마스터 −14 LUFS, true peak ≤ −1 dBTP, AAC 인코딩 후 재측정.
5. 검사: check → 박마다 1프레임 스냅샷 → 렌더 → frozen_time.sh, frame_pops.py(의도한 컷 --allow), loudness.sh → 새 크리틱.
</build>

<gotchas>
- <예: 흰 카드가 흰 페이지에서 사라짐 → 1px 헤어라인 + 옅은 그림자>
- <예: flood 전환은 모서리 넘게 스케일, 0.3s>
- <G3에서 발견한 것을 여기에 추가>
</gotchas>

<start>
G3 정지 프레임: b4, b8, b16, b28 (4장) → 승인 후 애니메이션 → 렌더 → 크리틱 → G4.
</start>
```

## 쓰는 요령

- **효과 이름보다 원칙과 금지.** "파티클 + 글로우 + 3D"를 나열하면 기본값 쇼릴이 나온다. 한 줄 원칙과 금지 목록이 방향을 고정한다.
- **구조는 넘겨지는 물체로 쓴다.** 장면마다 "A의 무엇이 B의 무엇이 되는가"가 비어 있으면 그 전환은 슬라이드쇼다.
- **수치는 측정 가능하게.** "빠르게" 대신 "0.3s", "크게" 대신 "화면의 70%", "약간" 대신 "1.0→1.04".
- **모르는 건 비워 두지 말고 기본값을 적는다.** 빌더가 추측하지 않게.
- 길이: 15초 영상이면 한 화면 분량(40–80줄)이 적당하다. 프레임 단위 표는 참조를 정밀 재현할 때만 쓴다.
- 스펙을 바꾸는 노트(G4)가 오면 코드보다 스펙을 먼저 고치고, 바꾼 줄을 보고한다.
